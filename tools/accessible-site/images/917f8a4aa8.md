# alt
Diagramma Git Flow di Vincent Driessen: branch master, hotfixes, release, develop e feature nel tempo, con i tag 0.1, 0.2 e 1.0.
# descrizione
Diagramma disegnato a mano con il tempo che scorre dall'alto verso il basso (freccia verticale "Time" a sinistra). Cinque colonne, da sinistra a destra: "feature branches" (cerchi rosa), "develop" (cerchi gialli), "release branches" (cerchi verdi), "hotfixes" (cerchio rosso) e "master" (cerchi azzurri). Ogni cerchio è un commit e le frecce indicano i merge. In alto "master" ha il commit etichettato "Tag 0.1"; da lì parte "develop". Dalle feature branch, create da develop, i commit vengono riuniti in develop quando la funzione è pronta ("Major feature for next release", "Feature for future release"). Un hotfix parte da master per correggere un bug grave in produzione ("Severe bug fixed for production: hotfix 0.2"), viene riunito in master con "Tag 0.2" e anche in develop ("Incorporate bugfix in develop"). Poi da develop parte una release branch ("Start of release branch for 1.0"): da quel punto "next release" significa la release successiva alla 1.0; sulla release branch si fanno "Only bugfixes!", che possono essere riportati in continuazione in develop ("Bugfixes from rel. branch may be continuously merged back into develop"); alla fine la release branch viene riunita in master con "Tag 1.0" e in develop. In fondo una nuova release branch porta a un ulteriore commit su master.
# testo
Colonne: feature branches; develop; release branches; hotfixes; master. Asse: Time.
Fumetti: "Tag 0.1"; "Tag 0.2"; "Tag 1.0"; "Feature for future release"; "Major feature for next release"; "Severe bug fixed for production: hotfix 0.2"; "Incorporate bugfix in develop"; "Start of release branch for 1.0"; "From this point on, 'next release' means the release after 1.0"; "Only bugfixes!"; "Bugfixes from rel. branch may be continuously merged back into develop".
